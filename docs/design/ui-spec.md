# Shellora 界面规范（单源）

> 本页是界面度量的唯一来源。令牌定义在 [`src/styles/base.css`](../../src/styles/base.css) 的 `:root` 中；
> 守卫脚本为 [`scripts/check-spacing.mjs`](../../scripts/check-spacing.mjs)、
> [`scripts/check-ui-metrics.mjs`](../../scripts/check-ui-metrics.mjs)、
> [`scripts/check-ui-spec.mjs`](../../scripts/check-ui-spec.mjs)，CI 全量执行。
> 与历史审计的关系：本文取代 `spacing.md` 中的取值表，`spacing.md` 保留改造记录。

## 0. 三条硬规则

1. **组件里不写裸度量值。** 间距、字号、行高、圆角、描边、控件尺寸、图标尺寸、动效时长只能引用令牌。
2. **只允许表里的档位。** 需要新档位时先改本页与令牌，再改组件；禁止就近造一个 7px / 13.5px。
3. **同一语义只有一个答案。** 两种“差不多”的尺寸同时存在就是缺陷，按本页收敛，不保留兼容分支。

平台常量（如 macOS 红绿灯让位 78px）在声明行尾写 `/* no-sp-token: 理由 */`，
脚本放行但要求写明理由；除此之外不接受例外。

## 1. 间距标尺

| 令牌 | 值 | 语义用途（应该用） | 不该用（反例） |
| --- | ---: | --- | --- |
| `--sp-0` | 2px | 图标与文字的光学贴合、两个贴合小标签之间 | 按钮左右内边距；表单项之间 |
| `--sp-1` | 4px | 紧凑控件内部：图标按钮图标与边框、标签内文字与 × | 卡片内边距；区块之间 |
| `--sp-2` | 8px | 控件之间、图标与文字、列表行内两段信息的间隔 | 页面级留白；面板四边内缩 |
| `--sp-3` | 12px | 行内左右留白、面板边界、工具栏元素间距 | 大区块之间的分隔（应用 24） |
| `--sp-4` | 16px | 工具栏与内容、卡片内边距、状态栏左右 | 两行文字之间（行高负责） |
| `--sp-5` | 24px | 区块之间、表单分组之间 | 列表行之间（行高负责） |
| `--sp-6` | 32px | 页面级留白、大区块上下 | 图标与文字 |
| `--sp-7` | 48px | 空状态、引导区的上下留白 | 常规卡片 |

**应该用**

```css
.srow { height: var(--row-md); padding: 0 var(--sp-3); gap: var(--sp-2); }
```

**不该用**

```css
.srow { padding: 0 10px; gap: 7px; }   /* 10/7 都不在档位 */
```

负间距只允许写成 `calc(var(--sp-N) * -1)`，禁止直接写 `-8px`。

## 2. 字号阶梯

每一档固定行高；**同一规则里同时写 `font-size` 与 `line-height` 时，行高不得低于该字号的配对标高**
（例如 12px 正文不得配 15px 行高；确有单行定高需求时用 `--lh-none`）。

| 令牌 | 字号 | 行高令牌 | 行高 | 字重 | 字距 | 用途 |
| --- | ---: | --- | ---: | --- | --- | --- |
| `--fs-2xs` | 10px | `--lh-2xs` | 13px | `--fw-semibold` | `--ls-caps` | **仅辅助**：计数、角标、单位、时间戳、`kbd` |
| `--fs-xs` | 11px | `--lh-xs` | 15px | `--fw-medium` | `--ls-wide` | **仅辅助**：等宽元信息、全大写分组标签、图表刻度 |
| `--fs-sm` | 12px | `--lh-sm` | 16px | `--fw-medium` | `--ls-normal` | **正文下限**：字段标签、列表主行、紧凑控件、状态文字 |
| `--fs-md` | 13px | `--lh-md` | 18px | `--fw-regular` | `--ls-normal` | 正文（默认，`body` 使用） |
| `--fs-lg` | 15px | `--lh-lg` | 20px | `--fw-semibold` | `--ls-tight` | 区块标题、卡片标题 |
| `--fs-xl` | 17px | `--lh-xl` | 22px | `--fw-semibold` | `--ls-tight` | 页面 / 面板标题 |

原 9px 档已取消，`--fs-2xs` 抬到 10px 作为下限；原 17px 的 `--fs-2xl` 与 `--fs-xl` 合并（视觉尺寸不变）。


特殊行高：

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--lh-none` | 1 | 单行定高控件（状态栏单元格、徽标） |
| `--lh-flat` | 1.2 | 12px 以内的单行标签 |
| `--lh-prose` | 1.5 | 多段说明文字、更新日志 |

字重：`--fw-regular` 400 / `--fw-medium` 500 / `--fw-semibold` 600 / `--fw-bold` 650。
字距：`--ls-tight` -0.01em / `--ls-normal` 0 / `--ls-wide` 0.02em / `--ls-caps` 0.08em / `--ls-caps-wide` 0.12em。

**应该用**

```css
.cfhead2 h3 { font-size: var(--fs-xl); line-height: var(--lh-xl); font-weight: var(--fw-semibold); letter-spacing: var(--ls-tight); }
```

**不该用**

```css
.cfhead2 h3 { font-size: 18px; line-height: 1.35; letter-spacing: 0.2px; }
```

反例说明：18px 与 17px 只差 1px，却会让标题在不同面板里飘；行高写倍数则无法与字号成组。

### 2.1 字号下限与辅助字号白名单

- **下限 10px**：阶梯最低档是 `--fs-2xs` = 10px，任何声明不得低于它。
- **10/11px 只承载辅助信息**：计数、角标、单位、时间戳、`kbd`、等宽元信息、全大写分组标签。
  **正文、按钮、表头、字段名、标签页、面包屑、状态句子一律 ≥ 12px（`--fs-sm`）**。
- 检查器按 `AUX_FS_ALLOW` 白名单执行：选择器用 10/11px 但不在白名单里，直接失败并指出行号。
  白名单条目按类别登记（下表），新增条目必须同时改 `scripts/check-ui-spec.mjs` 与本表。

| 类别 | 允许档位 | 典型选择器 |
| --- | --- | --- |
| 计数 | 10 / 11 | `.count`、`.num`、`.cnt`、`.cnt2`、`.ffoot`、`.dops__sel`、`.applyrow .r` |
| 角标 / 单位 | 10 | `.qbadge`、`.warnchip`、`.hostchip`、`.tagrow`、`.scope`、`.opt`、`.sz`、`.pct`、`.rate`、`.eta`、`.upd-size` |
| 时间戳 | 10 / 11 | `.dt`、`.upd-date` |
| 等宽元信息 | 11 | `.meta`、`.meta2`、`.xmeta`、`.sub`（`user@host` / 路径）、`.fingerprint dd`、`.drawer__host`、`.drawer__w`、`.upd-from`、`.upd-title p`、`.upd-progress__meta`、`.upd-error__code` |
| 图表 / 分隔 | 10 | `.axis .lbl`、`.sep` |
| 全大写分组标签 | 11 | `.glabel`、`.avatar`（首字母）、`.usercard`、`.qchild` |
| 状态栏 | 11（新布局 12） | `.statusbar`（路径 / 计数 / 模式） |

**应该用**

```css
.frow .sz { font-size: var(--fs-2xs); }   /* 单位：体积 */
.qrow2 .rate { font-size: var(--fs-2xs); } /* 单位：速率 */
.field2 .lb2 { font-size: var(--fs-sm); }  /* 可读字段名 → 12px */
```

**不该用**

```css
.prose { font-size: var(--fs-2xs); }   /* 正文 10px，检查器报“不得低于 12px” */
.hint { font-size: var(--fs-xs); }     /* 说明句 11px，同上 */
```

### 2.2 DPI 与缩放：**没有**全局反缩放（结论先说）

`--fs-*` 是绝对 CSS px，全站没有 `zoom`、没有 `transform: scale()`、没有 `html { font-size }` 的 rem 基准、
也没有 `text-size-adjust`，因此：

- **Windows 缩放（125%/150%/200%）对 CSS px 无影响**，只是把 1 CSS px 映射成更多物理像素；
  10px 在 200% 下渲染成 20 物理像素，物理尺寸等于 100% 下的 20px 字号，不会“变小”。
- 真正会挤压布局的是 **WebView2 页面缩放**（`Ctrl + 滚轮` / `zoom factor`）：CSS 视口按比例缩小，
  字号仍是 10–17 CSS px，可用空间减半。唯一需要防的场景已由**最小窗口 640×480**兜住：
  更窄的视口（原 444×297 档）没有布局模型，窗口下限设为 640×480 后不可达，矩阵也不再设该档。
- 因此**不做**字号反缩放：`--fs-*` 若随缩放反向补偿，用户放大界面反而得到更小的字，
  与“放大是为了看清”直接冲突。

六档在四种缩放下的实际渲染尺寸（CSS px → 物理 px）：

| 令牌 | CSS | 100% | 125% | 150% | 200% |
| --- | ---: | ---: | ---: | ---: | ---: |
| `--fs-2xs` | 10 | 10 | 12.5 | 15 | 20 |
| `--fs-xs` | 11 | 11 | 13.75 | 16.5 | 22 |
| `--fs-sm` | 12 | 12 | 15 | 18 | 24 |
| `--fs-md` | 13 | 13 | 16.25 | 19.5 | 26 |
| `--fs-lg` | 15 | 15 | 18.75 | 22.5 | 30 |
| `--fs-xl` | 17 | 17 | 21.25 | 25.5 | 34 |

可读下限用**对比度**兜底，而不是靠放大：10–12px 的次要文字必须对**所有**承载背景 ≥ 4.5:1。
实测（`--text-3` 已由 `#8b97a5` / `#6c7b8a` 调整为下表取值，原值在浅色下仅 2.97:1、深色下 3.79:1，不合格）：

| 主题 | 前景 | vs `--bg` | vs `--surface` | vs `--surface-2` | vs `--surface-3` |
| --- | --- | ---: | ---: | ---: | ---: |
| 深色 | `--text-1` | 14.06 | 13.06 | 13.65 | 12.04 |
| 深色 | `--text-2` | 7.29 | 6.77 | 7.08 | 6.24 |
| 深色 | `--text-3` | 5.43 | 5.05 | 5.28 | 4.65 |
| 浅色 | `--text-1` | 14.86 | 16.09 | 15.53 | 14.58 |
| 浅色 | `--text-2` | 5.50 | 5.96 | 5.75 | 5.40 |
| 浅色 | `--text-3` | 4.67 | 5.05 | 4.88 | 4.58 |

页面实测（`scripts/visual-matrix.mjs` 在 1440×900、887×593、640×480 与 887×593@2x 下遍历全部可见文字节点）：
实际出现过的字号只有 `10 / 11 / 12 / 13 / 15 / 17` 六档，无阶梯外字号、无低于 10px 的文字；
小字号文本最低对比度 4.58:1。

## 4. 图标尺寸与对齐

### 4.1 尺寸阶梯

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--icon-2xs` | 10px | 勾选、行内微图标 |
| `--icon-xs` | 12px | 标签页关闭、窗口控制、单选项点 |
| `--icon-sm` | 14px | 列表行图标、工具栏次图标 |
| `--icon-md` | 16px | 标准按钮图标、面包屑图标 |
| `--icon-lg` | 20px | 主导航、品牌标记内图标 |
| `--icon-xl` | 24px | 面板级操作、空状态辅助图标 |

同一图标的 `width` 与 `height` 必须同档（脚本逐条对比）。
线宽：`--isw-thin` 1.1（12px 小图标）/ `--isw-1` 1.5（默认）/ `--isw-2` 1.8（强调）/
`--isw-strong` 2（勾选标记）。

### 4.2 容器

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--box-sm` | 22px | 紧凑文件图标底 |
| `--box-xs` | 24px | 列表文件图标底 |
| `--box-md` | 26px | 终端条、最近连接 |
| `--box-lg` | 30px | 头像、品牌标记、会话图标 |
| `--box-xl` | 36px | 大图标容器 |

圆点：`--dot-xs` 6px（状态点）/ `--dot-sm` 8px（强调点）。

### 4.3 对齐规则

1. **图标列等宽**：同一列内图标容器统一 `--box-*`，图标本身统一下一档 `--icon-*`，容器居中。
2. **光学对齐**：文字与图标并排时，图标向左多让 `--sp-0`（2px）视觉才居中；禁止用 `margin-top: 1px` 手调。
3. **基线**：列表行内主文字与副文字共用同一左缘（`padding-left` 取 `--sp-3`），副文字只允许靠字号/颜色区分。
4. **图标与文字间距**：`--sp-2`；紧凑标签内用 `--sp-1`。

**应该用**

```css
.qrow2 .dtile { width: var(--box-xs); height: var(--box-xs); }
.qrow2 .dtile .ic { width: var(--icon-sm); height: var(--icon-sm); }
```

**不该用**

```css
.qrow2 .dtile { width: 24px; }
.qrow2 .dtile .ic { width: 13px; height: 15px; }  /* 宽高不同档，视觉被拉扁 */
```

## 5. 圆角、描边、阴影、分隔线

### 5.1 圆角

只有 **4 档**，唯一来源是 `base.css` 的令牌表；视图里不允许出现裸 `border-radius`，也不允许新增档位。

| 令牌 | 值 | 用途 | 判定口径 |
| --- | ---: | --- | --- |
| `--r-card` | 8px | 卡片、面板、抽屉、对话框、菜单浮层、终端外框 | 会包住其他内容的「面」 |
| `--r-control` | 6px | 按钮、图标按钮、输入框、搜索框、标签页、列表行、小方块、品牌标记 | 会被点、被填、被选中的一个「件」 |
| `--r-pill` | 999px | 进度条、日期胶囊、计数角标、分段控件外壳 | 高度远小于宽度、两端半圆 |
| `--r-full` | 50% | 头像、状态点、单选点、圆形图标按钮 | 正方形取正圆 |

规则：

1. **一个类只用一个档**。同一个类名（含 `.app--next` 前缀的变体）在多处出现时必须同档，否则视为「同一层级同类元素半径不一致」。
2. **嵌套时内层圆角 = 外层圆角 − 内边距**，不允许内外同值；内层沿用同一档位，不为嵌套新增令牌。
3. 容器必须登记在检查器的 `RADIUS_CARD_FAMILIES` 里；未登记的面默认按控件档校验（新增容器要显式登记，避免下一轮又长回 8 档）。
4. 窗口本体的圆角**不在这里**——由系统画，见 §5.4。

### 5.2 描边

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--bw-1` | 1px | 默认描边、分隔线、1px 高的装饰线 |
| `--bw-2` | 2px | 选中/拖放强调、2px 高的下拉指示线 |
| `--bw-focus` | 3px | 焦点环宽度（配合 `--focus` 阴影） |

描边颜色只能取 `--border` / `--border-soft` / 状态色 `*-line`。分隔线优先用 `border-bottom: var(--bw-1) solid var(--border-soft)`，
不要用 `height: 1px` 的 div。

### 5.3 阴影层次

| 令牌 | 用途 |
| --- | --- |
| `--shadow-1` | 抬升 1 级：标签页激活、搜索框、卡片 |
| `--shadow-2` | 浮层：下拉菜单、会话库、抽屉 |
| `--shadow-3` | 模态：对话框、粘贴拦截、更新卡片 |
| `--focus` | 焦点环，不用 outline 颜色代替 |

**应该用**

```css
.ctxmenu { border-radius: var(--r-card); box-shadow: var(--shadow-2); }
```

**不该用**

```css
.ctxmenu { border-radius: 10px; box-shadow: 0 8px 24px rgba(0,0,0,.42); }
```

### 5.4 窗口圆角：交给系统，不自绘

窗口**外框**的圆角与描边归操作系统，Web 层只负责窗口内部的卡片、面板、输入框（§5.1）。

| 平台 | 谁画圆角 | 实现 |
| --- | --- | --- |
| Windows 11 | DWM | `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUND`；描边配色由 `DWMWA_USE_IMMERSIVE_DARK_MODE` 跟随主题。见 `src-tauri/src/frame.rs` |
| macOS | AppKit | 保留系统装饰（`titleBarStyle: Overlay`），不另画窗口边框 |
| Linux | 无系统圆角 | X11 保持直角；Wayland 由合成器决定。**不做自绘圆角**，避免与合成器叠加出白边 |

> 窗口内部元素不受影响：圆角、阴影、描边照常自绘，两件事不要混。

**症状**：深色界面下，窗口四角与四边贴着一圈 1px 的浅色/白色细线，放大后像白色描边。

**产生它的那一层**：不是 CSS。逐层排除结果——

| 候选层 | 结论 | 证据 |
| --- | --- | --- |
| 窗口透明区被系统/DWM 填色 | 否 | 窗口未启用 `transparent`，`GWL_EXSTYLE` 无 layered 位 |
| 1px 浅色描边（CSS `border`） | 否 | `html/body/#root/.app` 全量检索无窗口级 `border` / `border-radius` / `box-shadow` |
| `box-shadow` 扩散 | 否 | 窗口层无 CSS 阴影；看到的扩散是 DWM 自己的窗口阴影 |
| `overflow:hidden` 子元素背景溢出 | 否 | 角部 16× 放大无矩形色块边界，只有沿弧线的单像素线 |
| 圆角抗锯齿 alpha 预乘 | 否（它是结果不是原因） | 弧线的抗锯齿由 DWM 绘制；像素序列是「桌面 → 阴影 → 1px 浅色 → 内容」 |
| **DWM 窗口边框** | **是** | `DwmGetWindowAttribute(DWMWA_VISIBLE_FRAME_BORDER_THICKNESS) = 2`（200% 缩放下即 1 CSS px）；`DWMWA_USE_IMMERSIVE_DARK_MODE = 0`，即应用是深色但没告诉 DWM，DWM 按**浅色**画这 2 个物理像素 |

A/B 对照（同一窗口，只改一个属性，取上边缘中点 2 个物理像素）：

| 配置 | 那 2px 的实际颜色 | 亮度 | 结论 |
| --- | --- | ---: | --- |
| 默认边框 + `IMMERSIVE_DARK_MODE = 0` | `#F6F3EB` | 243 | **白边**，就是它 |
| 默认边框 + `IMMERSIVE_DARK_MODE = 1` | `#8F9194` | 145 | 缓解但仍是一条浅灰线 |
| `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` | `#EEF4F9` | 243 | 更差：边框区露出桌面 |
| `DWMWA_BORDER_COLOR = #1E2A36`（深色 `--border`） | `#1E2A36` | 40 | 与界面分隔线同族，白边消失 |

所以只加暗色标志不够，窗口最外那 1px 必须显式取 `--border`。

**修在哪**：`src-tauri/src/frame.rs` 在窗口创建时显式声明 DWM 圆角；主题切换时同步
`DWMWA_USE_IMMERSIVE_DARK_MODE`，并把 CSS 的 `--border` 换算成 `COLORREF` 写给
`DWMWA_BORDER_COLOR`。前端 `syncWindowFrame()` 在首帧前和每次切换主题时下发。

**怎么证明不再产生**：读回 `corner=2`、`dark=1`、边框像素 = `#1E2A36`（与 `--border` 完全一致）；
未设置该颜色时为 `#F6F3EB`。三个值都可脚本复现，不依赖截图主观判断。

#### 5.4.2 macOS：圆角由 AppKit 画，代码路径可查

| 问题 | 答案 |
| --- | --- |
| 谁负责圆角 | AppKit / WindowServer。`src-tauri/tauri.macos.conf.json` 里 `decorations: true` + `titleBarStyle: "Overlay"` + `hiddenTitle: true`，即标准带装饰的 `NSWindow`（titled/resizable）；圆角遮罩与窗口阴影由窗口服务器在合成时裁剪 backing store，内容铺到标题栏下方不影响角部 |
| `frame.rs` 的 macOS 分支做了什么 | `ATTR_*` 常量与 `set_attr` 全部包在 `#[cfg(windows)]` 里；`init()` 与 `set_theme()` 的 `#[cfg(not(windows))]` 分支只有 `let _ = window;` / `let _ = (window, dark, border);`，即**空实现**。没有任何 AppKit 调用，也没有改 NSWindow 样式 |
| 有 CSS 或 canvas 参与吗 | 没有。`html, body, #root` 只设 `height/margin`（`base.css:262-267`），`.app` 只有 `background`，均无 `border-radius`；无 canvas 绘制窗口外框。圆角处不存在「自绘层」可发白 |
| 系统不提供圆角会怎样 | 窗口就是直角，**不会出现白边**——因为外框我们一像素都不画。触发场景：`decorations:false` 的无边框窗口（AppKit 对 borderless 不给圆角与阴影）、或未来系统策略变化。此时若产品仍要圆角，只有「整窗自绘 + 接管阴影」一条路，代价是与系统阴影/贴边动画不一致，**明确不做** |
| 能否给 macOS 截图 | **本次不能，原因不是「没有产物」**：`release.yml` 的 macos job 在 `macos-latest` 上跑 `pnpm tauri build --target universal-apple-darwin --bundles app,dmg` 并上传 `macos-bundles` artifact，v1.1.1 的 `Shellora.app.tar.gz` 就在其中。真正的原因是三条：① 现有产物是 1.1.1 的构建，**不含本轮改动**；② 本机是 Windows，跑不了 `.app`；③ 托管 runner 无人值守，没有可截图的 GUI 会话。故 §11.5 记「未验证」（出包链路见 `docs/release/README.md` §10） |

## 6. 动效

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--dur-1` | 90ms | 菜单出现、微反馈 |
| `--dur-2` | 120ms | 悬停、开关、标签切换 |
| `--dur-3` | 160ms | 进度、抽屉滑入、面板推挤 |
| `--dur-4` | 200ms | 布局变化（栅格列宽） |
| `--dur-alert` | 600ms | 需要引起注意的一次性脉冲 |
| `--dur-spin` | 900ms | 旋转加载 |
| `--dur-pulse` | 1200ms | 循环进度条 |

缓动：`--ease-out` = `cubic-bezier(0.2, 0.8, 0.2, 1)`（进入/展开）、
`--ease-standard` = `ease`、`--ease-in-out`、`--ease-linear`（进度）。

规则：只动 `transform` / `opacity` / `background-color` / `width`；禁止给 `height`、`top`、`left` 做过渡。
超过 200ms 的动效必须可被 `prefers-reduced-motion` 关闭（循环类动效一律关闭）。

**应该用**

```css
.drawer { transition: opacity var(--dur-3) var(--ease-out), transform var(--dur-3) var(--ease-out); }
```

**不该用**

```css
.drawer { transition: all .14s ease; }   /* all + 非令牌时长 */
```

## 7. 状态

| 状态 | 标准表达 | 令牌 | 不该用 |
| --- | --- | --- | --- |
| 悬停（图标按钮/菜单项） | `background: var(--state-hover)` | `--state-hover` = `surface-3` | 自造 `rgba(255,255,255,.06)` |
| 悬停（列表行） | `background: var(--state-hover-row)` | `--state-hover-row` = `surface-2` | 加 `transform: translateX(2px)` |
| 悬停（浮层内抬升） | `background: var(--state-hover-raised)` | `--state-hover-raised` = `surface` | 改边框宽度导致抖动 |
| 悬停（强调按钮） | `background: var(--state-hover-primary)` | `--state-hover-primary` = `accent-2` | 在 `:hover` 里直接写 `var(--accent-2)` |
| 悬停（危险） | `background: var(--state-hover-danger)` + 前景 `--danger` | — | 直接用红色背景 + 白字 |
| 悬停（窗口关闭键） | `background: var(--state-hover-close)` | `--state-hover-close` = `#e81123` | 在组件里硬编码系统红 |
| 按下 | `background: var(--state-press)`，不加位移 | `--state-press` | `transform: scale(.97)` |
| 选中 | `background: var(--selected)` + `box-shadow: inset 0 0 0 1px var(--selected-line)` | 已有 | 只改文字颜色 |
| 焦点 | `box-shadow: var(--focus)`，`outline: none` | `--state-focus` | 去掉焦点环 |
| 禁用 | `opacity: var(--state-disabled-opacity)` + `cursor: not-allowed` | 0.45 | 用 `color: #666` 手调 |

**应该用**

```css
.iconbtn:hover { background: var(--state-hover); color: var(--text-1); }
.btn:disabled { opacity: var(--state-disabled-opacity); cursor: not-allowed; }
```

**不该用**

```css
.iconbtn:hover { background: #1b2836; }      /* 绕过主题令牌 */
.btn:disabled { opacity: .4; }               /* 0.4 / 0.45 / 0.5 三套并存 */
```

## 8. 校验进 CI

| 脚本 | 管什么 | 失败条件 |
| --- | --- | --- |
| `pnpm lint:spacing` | 间距裸值、未定义令牌、档位外令牌 | 出现裸 px 间距 |
| `pnpm lint:metrics` | 命中区 ≥28、`ROW_H` 单源、表头/行同栅格、左栏 12px 节奏、同名选择器唯一 | 结构漂移 |
| `pnpm lint:ui` | 字号/行高/字重/字距/圆角/描边/图标/控件高/动效/状态色/禁用态是否来自阶梯；圆角只允许 4 档、容器/控件档位正确、同类元素同档；图标宽高同档；布局宽高必须在豁免清单内；TSX 内联裸值 | 任一不在阶梯、越档、同类两档并存、或裸值未登记豁免 |
| `pnpm lint:ui:self` | 负向自检：每类规则各注入一条故意违规，必须被捕获并给出 `base.css:行号` | 任一类漏检 |
| `pnpm lint:ui:radius` | 运行时圆角验收（headless）：计算值只能落在 4 档、同一选择器跨视图/跨 DPI 同值、圆角外侧 4px「角袋」不得出现比父层更亮的像素 | 越档 / 跨视图不一致 / 角袋发亮 |

### 8.1 实际输出（本机 2026-11-15）

```text
界面规范检查通过：字号 6 档（下限 10px，正文 ≥12px）/ 行高 6 组 + 3 特殊 / 圆角 4 档（卡片 8 / 控件 6 / 胶囊 / 全圆）/ 控件高 10 档 / 图标 6 档
最小窗口 640×480（更窄无布局模型，矩阵不设该档）
令牌引用 778 处 / 裸值 0 处 / 豁免 28 处
```

三个数字的口径：

- **令牌引用**：受检属性（间距、字号、行高、圆角、描边、控件/图标尺寸、动效、状态色）里取值为 `var(--*)` 的声明数。
- **裸值**：同一批受检属性里直接写字面值的声明数。此数必须为 0；出现即失败并打印行号。
- **豁免**：布局类宽高（`width`/`height`/`min-*`/`max-*`）中属于面板、画布、列宽、弹窗基准宽度等“布局自由度”的裸值条数。
  它们不进入控件阶梯，但**必须逐条登记**在 [`ui-spec-exemptions.json`](ui-spec-exemptions.json) 才能通过；
  `top`/`left`/`z-index` 等非尺寸属性不计入三数。

### 8.2 豁免清单

文件：`docs/design/ui-spec-exemptions.json`（受版本控制）。每条必填四个字段：

```json
{ "selector": ".searchbox", "property": "width", "value": "332px",
  "reason": "顶栏搜索框基准宽度，窄窗由 flex 收缩", "owner": "design-system" }
```

规则：

1. 只有 `width` / `height` / `min-width` / `max-width` / `min-height` / `max-height` 可以豁免；
   间距、字号、行高、圆角、描边、控件高、图标、动效、状态色**一律不得豁免**（脚本按属性白名单直接拒绝）。
2. `reason` 至少 4 个字符，未填或占位符会被脚本判为无效。
3. 样式改动后豁免未命中会报「豁免已失效」，必须同步删条目——清单只增不减说明没人清理。
4. 每次 CI 都会打印**豁免总数与全表**（选择器、属性、值、理由、豁免人），数量增长在日志里直接可见。

描边 2px、控件高 26px、图标 13px、状态色 `#1b2836`、动效 140ms、未登记宽高 333px、

## 9. 怎么新增 UI（照表搭，不返工）

1. **先归类**：这是列表行、按钮、标签、输入框还是浮层？
2. **抄高度**：从 §3 选控件高度与行高；命中区先满足 `--hit-min`。
3. **定字号**：从 §2 选一档，同时写配对的 `--lh-*`；标题才用 `--ls-tight`。
4. **摆间距**：从 §1 选档；同一容器内只用相邻两档，跨两级要说明理由。
5. **放图标**：容器取 `--box-*`，图标取 `--icon-*`，宽高同档，间距 `--sp-2`。
6. **收边**：圆角按 §5.1 选档，描边 1px，浮层用 `--shadow-*`。
7. **补状态**：悬停/按下/选中/禁用/焦点各写一条，全部用 §7 的令牌。
8. **跑四条检查**：`pnpm lint:spacing && pnpm lint:metrics && pnpm lint:ui && pnpm lint:ui:self`。
   若确实需要布局类宽高裸值，去 `ui-spec-exemptions.json` 加一条并写理由，不要就地放过。

示例（按规范新写的组件）见 `src/features/ui/SpecRow.tsx`。

## 10. 规范要改时，先改哪几处

顺序不能反，否则 CI 会拦下不完整的改动：

1. **本页表格**：先加/改语义行，写清“应该用/不该用”。
2. **令牌块**：`src/styles/base.css` 的 `:root` 增加或调整令牌值。
3. **阶梯数组**：`scripts/check-ui-spec.mjs` 的 `LADDER`（字号/行高/圆角/控件高/图标/动效）同步改。
4. **迁移组件**：把旧值一次性替换为新令牌（按“同类全量排查”原则，不逐处补丁）。
5. **跑 lint + 视觉矩阵**：四条 lint 通过；改了字号/文案/布局再跑 §11 的 `visual-matrix.mjs`，
   确认五语种在两档视口下仍无截断，并把新截图挂到偏差清单里。

若只是新增一个“用法说明”而不改值：只改第 1 步。

## 11. 五语种 × 视口回归（脚本化）

字号阶梯只有 6 档，但**文案长度是变量**：日文与西班牙语会把同一行撑长 30–50%。
所以规范不靠肉眼验收，用一个脚本把矩阵跑完。

### 11.1 怎么跑

```powershell
pnpm dev                                              # 起 1420，?preview=1 用夹具数据
node scripts/visual-matrix.mjs --out <截图目录>
```

脚本启动本机 Chrome/Edge 的 headless 实例，用 CDP（不依赖 Playwright）逐个语种设精确视口与 `devicePixelRatio`：

| 维度 | 取值 |
| --- | --- |
| 语种 | `zh-CN` / `zh-TW` / `en` / `ja` / `es`（`?preview=1&locale=xx`） |
| 视口 A | 1440×900 @1x —— 常用大窗 |
| 视口 B | 887×593 @1x —— 最小可用工作窗（此前的最小窗口） |
| 视口 C | 887×593 @2x —— 同一窗口在 200% DPI 下（布局应完全不变化，只有物理像素翻倍） |
| 视口 D | 640×480 @1x —— `tauri.conf.json` 的最小窗口下限（更窄不可达，见 §2.2） |
| 状态 | 主界面、文件面板、队列（展开）、连接页、设置页 |
| 区域 | 顶栏、左栏、文件表格、队列、连接页、设置页 |

444×297 那一档已删除：它对应 640×480 窗口再叠加 200% 页面缩放，窗口下限设为 640×480 后不可达，
规范也不为它维护布局模型。

夹具（`?preview=1`）只覆盖“有会话、有传输”的画面；“无会话空状态”在 Chrome 里跑不到
（夹具装不进真实 Tauri 窗口，见 §11.4），这一状态由真机抽验兜底，不要以为矩阵全绿就覆盖完了。

### 11.2 判定口径（每条都对应一个可测量的量）

| 项 | 判定 | 实现 |
| --- | --- | --- |
| 横向溢出 | 页面 `scrollWidth - clientWidth` 必须为 0 | `documentElement` |
| 越界元素 | 顶栏/左栏/队列/设置卡内元素的 `right` 不得越过视口 | 跳过滚动容器内的正常滚动内容 |
| 文本截断 | `Range` 量出的文字矩形不得超出裁切祖先；带 `title` 或用省略号的算“可恢复”，不计失败 | `Range.getBoundingClientRect()`（`scrollWidth` 对 inline 恒为 0，不可用） |
| 纵向挤压 | 定高容器内 `scrollHeight > clientHeight` 为 0 | `overflow-y: hidden` 的元素 |
| 字号 | 实际渲染字号必须全部落在 6 档内，且最小 ≥10px | `getComputedStyle().fontSize` 直方图 |
| 对比度 | ≤12px 的文字对实际背景 ≥ 4.5:1 | 逐元素取前景 + 向上找背景，WCAG 2.x 公式 |

有任一失败即 `exit 1`，输出到具体选择器。

### 11.3 下限抬到 10px 后的复核结果

### 11.4 WebView2 真机抽验（与 Chrome 对照）

矩阵跑在 Chrome/CDP 上，应用实际跑在 WebView2，所以至少要在真实窗口里抽验一遍：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"
pnpm tauri dev --no-watch      # 起真实窗口，CDP 直连 9222 量 getComputedStyle
```

两个只有真机才会遇到的事实，先说清楚，免得后面误读数据：

1. **夹具装不进去**：Tauri 会把 `window.__TAURI_INTERNALS__` 定义成不可重定义属性，
   `?preview=1` 的夹具赋值抛 `TypeError`、`defineProperty` 抛 `Cannot redefine property`，
   页面直接空白。所以真机跑的是**真实 IPC 的空状态**（`/`），不是夹具；
   夹具里那些“有会话 / 有队列”的画面仍然只由 Chrome 矩阵覆盖。
2. **窗口坐标就是 CSS px**：这台机器 200% 缩放，但 `GetWindowRect` / `MoveWindow`
   在 DPI 虚拟化下拿到的是 CSS 单位（实测 `outer 1453×907 ↔ inner 1440×900`、`dpr=2`），
   外框与客户区固定差 13×7。按差值 1:1 平移即可，乘 `dpr` 会过冲一倍、在原点与目标之间来回跳。

抽验 zh-CN / ja / es × 887×593 与 1440×900（真机 CDP 量，Chrome 同条件对照）：

| 项 | Chrome | WebView2 | 结论 |
| --- | --- | --- | --- |
| 正文 | 13px / 行高 20px | 13px / 20px | 一致 |
| 顶栏 | 40px 高，13px 字 | 40px / 13px | 一致 |
| 状态栏 | 28px 高，12px 字 / 20px 行高 | 28px / 12px / 20px | 一致 |
| 状态栏分级 | 887 隐 `cell--low`（6/7），1440 全显（7/7） | 6/7、7/7，槽位顺序与可见性逐项相同 | 一致 |
| 字体回退 | 系统 UI 栈 | Canvas 量宽三语种文本与 Chrome **逐条相同**（CJK / 假名 / 拉丁） | 一致 |
