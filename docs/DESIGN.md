# Shellora 界面设计 v2（终端优先，文件按需）

> 状态：已实施（`src/` 与本文一致），原型见 [`design/v2/`](../design/v2/)。
> 方案二（单一视区模式切换）保留为备选，不实施。

## 1. 目标与取舍

上一版把终端与文件双栏并排、外加 64px 顶栏 / 248px 常驻会话栏 / 32px 状态栏，实际长时间使用的问题有两个：

1. 终端与文件都只有半屏宽，两边都不好用；
2. 装饰性 chrome 占掉 344px 高度与 248px 宽度，真正干活的地方被挤压。

v2 的判断标准只有一条：**实际长时间使用是否顺手**。由此确定：

- 终端是唯一主视区，默认全宽；
- 文件（SFTP）按需呼出，不常驻；
- 所有 chrome 压缩到 92px，且不承载"只是好看"的内容。

## 2. 信息架构与单行骨架

自 2026-11-13 起不再有"系统标题栏 + 应用顶栏 + 会话条"三层：窗口改为无边框，**一行自绘标题栏同时承担系统标题栏与应用顶栏**，会话条并入同一行。

```
┌───────────────────────────────────────────────┐
│ 标题栏 36px  ⎇ Shellora │ 会话库·标签 │ 传输·文件·连接 │ ⓘ 主题 │ — □ ✕ │
├───────────────────────────────────────────────┤
│                                               │
│   终端舞台（全宽）            ┌──────────────┐  │
│                               │ 文件抽屉      │  │
│                               │（按需，可调宽）│  │
│                               └──────────────┘  │
├───────────────────────────────────────────────┤
│ 状态栏 26px  抽屉状态 · 宽度 · 传输摘要          │
└───────────────────────────────────────────────┘
```

| 区域 | 高度 | 内容 | 与上一版差异 |
|---|---|---|---|
| 标题栏 `.topbar` | 36px | 品牌图 + 应用名（拖拽区）· 会话库开关 · 会话标签 · 传输计数 · 文件 · 挤压/覆盖 · 连接 · 更新 · 主题 · 最小化/最大化/关闭 | 原 36 + 34 = 70px，后合并为 46px，二次压到 36px |
| 主视区 `.center--stage` | 自适应 | 终端卡片铺满（`padding: 8px`），抽屉浮动其上或挤压右侧 | 不变 |
| 状态栏 `.statusbar` | 26px | `文件面板 · 挤压中/覆盖中 · 420px` 或 `文件面板已收起` | 原 22px（字号上调后同步加高） |

固定 chrome 合计 **62px**（36 + 26），比合并后的 72px 再少 10px，比最初 92px（36+34+22）少 30px，旧版还有 248px 常驻侧栏。

### 2.2 自绘标题栏

- **无边框**：Windows / Linux 用 `decorations: false`（`tauri.windows.conf.json` / `tauri.linux.conf.json`），窗口背景与 `--bg` 令牌一致，不会再出现系统栏那条异色。
- **macOS**：保留原生红绿灯，`decorations: true + titleBarStyle: "Overlay" + hiddenTitle: true`（`tauri.macos.conf.json`），顶栏左侧留 78px 给按钮，自绘窗口控制隐藏。
- **窗口行为**：Windows 上空白区拖动、双击最大化、最大化按钮点击都交给系统（见下「原生命中测试」）；macOS/Linux 仍用 `startDragging()` 拖动、`mousedown.detail === 2` 双击最大化；`ResizeHandles` 提供 8 个方向的 4px（四角 12×12）热区调用 `startResizeDragging()`；最小化/最大化-还原/关闭为 40×35 按钮（命中 40×36，悬停 `--surface-3`、按下 `--surface-2`、关闭悬停 `#e81123`），贴右边缘；最大化后根节点去掉边框，按钮区不越界。

- **Windows 原生命中测试（1.0.8）**：`src-tauri/src/caption.rs` 在窗口 WndProc 上做 `WM_NCHITTEST` 覆盖——
  - 标题栏空白拖拽区 → `HTCAPTION`：系统自己的非客户区拖动循环接管拖动，于是 Win11 贴靠、拖到屏幕上/左/右半屏、拖到顶部最大化都回归；
  - 最大化按钮 → `HTMAXBUTTON`：Windows 11 只认这个命中码来弹「贴靠布局」，现在悬停即可弹出；
  - 其余位置（最小化/关闭、标签、文件/覆盖/连接、搜索框、内容区）不拦截，原样交回 Tauri/tao 的 WndProc，DOM 事件完全不受影响。
  - 区域来源：前端量测（顶栏中线 4px 步长采样、排除 `button/input/[role=button]` 等控件、上下左右各让出 4px 给缩放热区），标签增删 / 窗口缩放 / 最大化时重算，经 `window_caption_regions` 下发（CSS px + `devicePixelRatio`）；量不到时 JS 的 `startDragging` 仍是兜底。
  - 双击：`WM_NCLBUTTONDBLCLK` + `HTCAPTION` 时自己 `PostMessage(SC_MAXIMIZE/SC_RESTORE)` 并 `return 0`，只切一次；该区域 DOM 收不到 mousedown，JS 双击分支不会重复触发。
  - 命中区内的悬停：`HTMAXBUTTON` 区域拿不到 DOM 鼠标事件，WndProc 在 `WM_NCHITTEST`/`WM_NCMOUSEMOVE` 上转发 `shellora://caption` 事件，按钮补 `wc--hover`；按下由 `WM_NCLBUTTONDOWN` 直接切换最大化。
  - 前提：窗口 style 需带 `WS_THICKFRAME|WS_MAXIMIZEBOX|WS_MINIMIZEBOX|WS_SYSMENU`（无边框窗口默认已有，缺位时启动补上）。
- **平台差异**：

| 平台 | 标题栏 | 拖动 | 缩放 | 窗口按钮 | 贴靠布局 |
|---|---|---|---|---|---|
| Windows 10/11 | 自绘 | 系统 caption 拖动（`HTCAPTION`） | 八向热区 + `WS_THICKFRAME` | 自绘（40×35，最大化按钮走原生命中） | Win11 悬停最大化按钮弹原生贴靠布局；`Win+Z` 同样可用 |
| macOS | 原生 Overlay + 自绘内容 | `startDragging` | 原生红绿灯 | 原生红绿灯 | 原生绿色按钮的菜单保留 |
| Linux（GNOME/KDE 等） | 自绘 | `startDragging`（由窗口管理器处理移动） | 八向热区（`startResizeDragging` 交由 WM/Wayland 合成器） | 自绘 | 不适用 |

- **多显示器 / DPI**：尺寸、位置全部由窗口管理器按物理像素处理，自绘部分只用 CSS px（36px 标题栏在 200% DPI 下为 72 物理像素），`isMaximized()` + `onResized` 同步按钮图标；最大化走系统 work area，不会盖住任务栏，也没有额外黑边。

### 2.4 图标语义：一图一义

规则：

- 一个图形只对应一个功能；同一功能出现在两个位置（顶栏、抽屉）时必须复用同一图形。
- 功能不同但位置相邻，必须换图形家族——轮廓、方向、量感至少一项明显不同，不允许只靠 tooltip 补救，也不允许只差一条 3px 竖线。
- 状态（当前是哪种模式）由图形本身表达；`aria-pressed` / `aria-label` 同步描述动作与当前态，tooltip 只做补充，不承担语义。
- 尺寸口径：命中区 28×28，图标 15px；默认无文字，悬停就地展开 12.5px 文字，不换行。

三族划分（顶栏与抽屉一致）：

| 家族 | 图形语言 | 用于 | 关键特征 |
|---|---|---|---|
| 侧栏 / 会话库 | 外框 + 左侧实心板（面） | `.sb-toggle`、`.rail-toggle` | 只有一块实心面，内部无线条 |
| 管道布局 | 线稿（线） | 覆盖 = 层叠菱形；挤压 = 双栏 + 左栏全高竖线 | 覆盖是两层斜向菱形；挤压是两块开放栏，无底边 |
| 对象 | 具象轮廓 | 文件 folder、主机 server、终端 terminal、新建 plus、关闭 x | 同形同义，跨位置复用 |

为什么「挤压」不用底边：带底边时轮廓像"托盘上的两块方块"，15px 下与「覆盖」的堆叠语感接近，也容易被读成数字 00；去掉底边并把两栏拉高（9.6 → 12.4），再在左栏加一条全高分隔线，"并排"只靠竖向结构表达。

旧图标去向：`panel`（矩形 + 竖线，一图三用：会话栏开关、会话库开关、模式按钮）拆成 `sidebar` / `layers` / `columns`；`split`（竖线居中、无引用）删除。

## 3. 终端舞台

- 终端卡片 `.termcard--stage` 占满主视区，圆角 8px，无额外标题栏按钮（原"收起"按钮已移除，终端不再可折叠）。
- 抽屉收起时终端宽度 = 视口宽 − 16px（左右 8px 内边距），实测 1440 视口下 1424px。
- 抽屉 push 形态下终端让位：`margin-right: calc(var(--panel-w) + 6px)`，过渡 140ms。
- overlay 形态下终端保持全宽，抽屉浮在其上。

## 4. 文件抽屉

### 4.1 形态

| 形态 | 终端 | 适用 |
|---|---|---|
| `push`（默认） | 右侧让出面板宽度 | 需要边看文件边敲命令 |
| `overlay` | 保持全宽，抽屉覆盖 | 窄窗口、临时看一眼文件 |

窗口初始宽度 < 1360px 时自动切 `overlay`；会话条「挤压/覆盖」按钮可手动切换；`Alt+P` 亦可。

### 4.2 宽度规则

| 项 | 规则 |
|---|---|
| 默认宽度 | ≥1700px → 460；1360–1699 → 420；<1360 → 380 |
| 最小宽度 | `min(340, max(280, round(vw × 0.42)))` |
| 最大宽度 | `max(min, min(720, round(vw × 0.56), vw − 560))` |
| 夹取时机 | 拖动时、键盘调节时、窗口尺寸变化时、读取存储值时 |
| 传递方式 | CSS 变量 `--panel-w`（作用于 `.center--stage`） |

`vw − 560` 保证 push 形态下终端至少留 560px，不会把终端压成一条缝。

### 4.3 交互

- **拖动**：`.drawer__grip` 上 `pointerdown` + `pointerCapture`，rAF 合并 `pointermove`；拖动中根节点加 `.app--resizing`（`cursor: col-resize`、禁用选择与过渡），避免重排抖动。
- **双击**：分隔条双击回到该视口的默认宽度。
- **键盘**：`Alt+[` / `Alt+]` 每次 ±40px，按住 Shift ±120px；分隔条聚焦时 `←` / `→` ±20，`Home` 回默认。
- **宽度气泡**：拖动中在抽屉左缘显示 `420px` 胶囊，松手即消失。
- 拖动与宽度变化不影响呼出/收起动画，也不改写终端滚动位置。

### 4.4 持久化

| 键 | 内容 | 作用域 |
|---|---|---|
| `shellora.panelWidth:<sessionKey>` | 该会话的抽屉宽度（px） | 按会话 |
| `shellora.panelWidth` | 旧全局键，仅作首次兜底 | 全局 |
| `shellora.sftpPath.<tabId>` | `{ local, remote }` 双栏当前路径 | 按标签 |
| `shellora.queueOpen` | 传输队列折叠态 `0/1` | 全局 |

关窗重开、切换会话、重启应用后宽度与路径都会恢复；窗格变窄时只临时夹取，不回写覆盖用户选择。

### 4.5 内容布局

抽屉内不再并排双栏（420px 下会挤成两半），改为**单页切换**：

- 头部：`文件` + 主机名 + 当前宽度 + 关闭按钮（重复的 `Files` 标题与 hostchip 在抽屉内隐藏）；
- 一级切换：`远端` / `本机`；
- 常驻操作行 `.dops`：上传、新建目录、下载、重命名、删除（未选中时仅"新建目录"可用）；宽度 < 420px 时自动收成图标（`title` 保留文字提示），保证 5 个按钮在任何允许宽度下都不被挤出；
- 行内编辑器 `.dedit`：新建/重命名共用，Enter 提交、Esc 取消、自动聚焦并选中原名；
- 传输队列：默认展开，高度上限 168px，表头箭头可折叠到 46px（计数与速度仍可见）。

## 5. 文件操作入口

| 操作 | 入口 |
|---|---|
| 上传 | 操作行 `上传`、`Alt+U`、右键菜单、从系统文件管理器拖入窗口 |
| 下载 | 操作行 `下载`、右键菜单（远端行） |
| 新建目录 | 操作行 `新建目录`、`Alt+N`、右键菜单 |
| 重命名 | 操作行 `重命名`、`F2`、右键菜单 |
| 删除 | 操作行 `删除`、`Delete`、右键菜单 |
| 复制路径 | 右键菜单 |
| 路径插入终端 | 把文件行拖到终端（补尾空格；按住 Shift 单文件生成 `cd <dir> `） |

远端与本机语义差异：

- 删除目录都要求目录为空，不做递归删除；
- 本机删除不进回收站；
- 本机重命名拒绝覆盖同名目标。

键盘路由只在抽屉可见时注册（`active`），焦点在输入框内不拦截。

## 6. 会话库

原 248px 常驻侧栏改为**按需浮层**：会话条左侧按钮开关，浮层宽 248px、覆盖主视区、带半透明遮罩（点击遮罩关闭），不做宽度过渡动画以免与终端布局互相拉扯。窗口初始状态下默认收起。

## 7. 主题与品牌

- 亮/暗两套令牌定义在 `src/styles/base.css` 的 `:root` 与 `[data-theme="dark"]`。
- 顶栏品牌图随主题切换：暗色用 `shellora-dark.svg`，亮色用 `shellora-light.svg`；程序图标（`src-tauri/icons/`）统一使用暗色版。

## 8. 方案二（备选，不实施）

`design/v2/concept-b-single-surface.html`：单一视区 + 顶部模式切换（终端 / 文件互斥全屏），切换保留各自状态。

- 优点：宽度永远满格，窄窗口下最从容；
- 代价：无法边看目录边敲命令，"看一眼再回来"需要两次切换；
- 结论：作为窄屏或后续"专注模式"的备选保留，当前不实施。

## 10. 最小可用尺寸

- 窗口下限 `minWidth: 900` / `minHeight: 600`（`src-tauri/tauri.conf.json`）。
- 900 宽时抽屉宽度被夹到 `max(min, min(720, 504, 340))`，此时 < 420px 触发紧凑操作行，5 个按钮只留图标、全部可点，无裁切。
- 600px 高时终端可用高度约 492px（92px chrome + 16px 内边距），抽屉内列表与队列各自滚动，不出现控件消失。

## 12. 已知偏差与后续

- 会话库浮层无进出动画（有意为之，避免与终端布局竞争）。
- 2026-11-13 修复：终端窗格曾因遗留的 `terminalOpen` 状态恒为 `false` 而一直 `visibility: hidden`（现象是连上后终端一片空白），已改为按激活标签直接渲染。
- 本机与远端目录删除都不递归，删除非空目录会报错。
- 外部文件拖入依赖 Tauri 原生 drag-drop 事件，浏览器预览环境下不可用。
- 2026-11-13 修复：SSH 客户端曾设 `inactivity_timeout = 60s`，空闲一分钟即被自身拆链，表现为 SFTP 传输后通道莫名 EOF；已改为 `None`，不再按空闲时长主动断开。
- 2026-11-13 修复：`tab_id` 在握手完成前就返回给前端，抽屉首帧的远端列表可能抢在会话就绪前发出而报 `CHANNEL_CLOSED`；SFTP 侧 `open_stream` 现在等句柄就绪（100ms 轮询，上限 8s）。
- 方案二的"单视区"思路可在窄窗口下作为独立模式再评估。
