# 版本号规则

Shellora 采用三段式版本号：`MAJOR.MINOR.PATCH`。

## 1. 硬性上限

**除 MAJOR 之外，任何一段都不得超过 10**，即 MINOR 与 PATCH 的合法取值是
`0` 到 `10`，不允许出现 11 及以上的段值。MAJOR 不受此限。

示例：

- 合法：`1.0.0`、`1.0.10`、`1.2.7`、`12.10.10`
- 非法：`1.0.11`、`1.11.0`、`1.3.12`

## 2. 进位规则

| 场景 | 做法 | 示例 |
| --- | --- | --- |
| 修 bug / 小改动 | PATCH +1 | `1.2.3` → `1.2.4` |
| PATCH 已到 10，再来一个补丁 | MINOR +1，PATCH 归零 | `1.0.10` → `1.1.0` |
| 新功能 | MINOR +1，PATCH 归零 | `1.1.3` → `1.2.0` |
| MINOR 已到 10，再来一个新功能 | MAJOR +1，MINOR/PATCH 归零 | `1.10.4` → `2.0.0` |
| 破坏性变更 | MAJOR +1 | `2.4.1` → `3.0.0` |

总结成一句话：**patch 到 10 进 minor，minor 到 10 进 major**。

## 3. 预发布

需要灰度或内部验证时使用后缀：`-alphaN`、`-betaN`、`-rcN`，`N` 同样不得超过
10（如 `1.2.0-beta3`，不允许 `1.2.0-beta11`）。正式发布时去掉后缀。

## 4. 当前版本

- 上一个正式版：`1.0.10`（PATCH 已到上限）
- 当前开发版：`1.1.0`（间距体系 + 五语种界面）
- 下一补丁位：`1.1.1`，再往上是 `1.1.10`，之后必须进 `1.2.0`

## 5. 校验

`scripts/check-version.mjs` 在 CI 中执行，检查：

1. `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 三处版本一致；
2. 上述文件与 `README.md`、`docs/VERSIONING.md`、`docs/release/manifest-*.json`
   里的版本字面量都符合「非首位 ≤ 10」；
3. 历史 git tag（`v1.0.0` 起）逐条复核；
4. 扫描时屏蔽误伤：IPv4 地址、四段式数字、端口、依赖声明行（`"^1.2.3"`、
   `cargo` 的 `foo = "1.2"`）、以及 Qt / Node / Tauri / React 等第三方版本。

任何一条不合规，CI 直接失败。
